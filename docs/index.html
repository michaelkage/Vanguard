02 / CONTRACT

Protocol v1 envelope

The author signs one immutable unsigned representation. Both the event ID and signature cover those same bytes; ID and signature themselves are excluded. Relay metadata must stay outside the signed envelope.

Field contract

FieldMeaning
versionInteger; current protocol version is 1.
idBase64url without padding; SHA-256 of canonical unsigned UTF-8 bytes.
typeLowercase identifier matching [a-z][a-z0-9_.-]{0,63}.
authorPublicKeyBase64url-no-padding X.509 SubjectPublicKeyInfo Ed25519 public key.
createdAtEpochMsAuthor-declared Unix timestamp in milliseconds.
expiresAtEpochMsOptional expiry timestamp, later than creation.
payloadCanonicalJsonObject-shaped JSON text supplied by the event-type layer.
signatureBase64url-no-padding Ed25519 signature over unsigned bytes.

Verification order / EventProtocol.verify

  1. Reject unsupported protocol version.
  2. Rebuild the unsigned event with fixed field order.
  3. Recompute SHA-256 and compare event ID.
  4. Check expiry only when a clock value is supplied.
  5. Decode signature; verify Ed25519 against author public key.
  6. Return true only after every check passes.
Important: a valid signature proves control of a private key. It does not prove a student's real-world identity, campus membership, or current authorization.

Canonical unsigned representation

{
  "version": 1,
  "type": "message.created",
  "authorPublicKey": "<base64url-SPKI>",
  "createdAtEpochMs": 1800000000000,
  "expiresAtEpochMs": null,
  "payload": {"body":"hello"}
}

The Kotlin codec uses fixed field order and JSON string escaping. It is not a claim of full RFC 8785 / JCS compliance. Payload JSON is expected to be canonicalized upstream; the current core checks only that trimmed input begins with { and ends with }—it does not parse or canonicalize arbitrary JSON.

The Android repository intentionally does not verify signatures itself. Callers must verify first. Its transaction inserts the full envelope and queue item atomically; the event's signed fields are copied without rewriting.

04 / BOUNDARIES

Implemented ≠ production-ready

The unfinished pieces are architectural dependencies, not cosmetic TODOs. The prototype must not be presented as a deployable campus messenger or identity system.

Present in source

  • Protocol v1 immutable author-signed envelope.
  • Fixed-field unsigned encoding, SHA-256 event IDs, Ed25519 reference signer/verifier.
  • Version, field-shape, event-ID, signature and optional expiry checks.
  • Transport-independent event-store and relay-queue interfaces with in-memory adapters.
  • Room-backed Android event table and durable relay queue.
  • Atomic verified-event + queue insertion, deduplication, bounded batches, ack and retry deferral.

Not implemented / constraints

  • Android Keystore-backed signing or production Android key provider.
  • Android application/UI shell; this repository builds a library, not an installable app.
  • BLE / Wi-Fi Direct discovery, transport, authenticated peer sessions or encryption.
  • Enrollment, campus membership, key rotation, revocation and trust freshness.
  • Supabase synchronization, server-side validation, PlugScore integration.
  • Strict payload schemas, parser hardening, payload size limits, cross-language test vectors.
  • Application-level Room database encryption; instrumentation and migration tests.
Security warning. JVM Ed25519 keys are a development/test reference, not persistent production key custody. Room data has no application-level encryption. Treat payloads as sensitive; do not store real private messages or identity records. Do not use this prototype for payments, emergency services, or high-value authorization.
The v1 wire contract also calls out stale offline revocation snapshots, provisional offline marketplace vouches, relay quotas / hop limits / TTL, replay and rate controls, and server idempotency as production requirements.
