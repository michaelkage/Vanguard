Vanguard is a signed-event and store-carry-forward communication foundation for campus environments with unreliable internet. Devices exchange bounded packets nearby, retain verified events, and are intended to sync them when an authoritative gateway is reachable.

01 / Packet lab

INTERACTIVE · LOCAL ONLY

Generate an actual Ed25519 keypair in this browser, sign a Vanguard-shaped event, frame it as a relay packet, then run signature and author-policy gates. This lab uses WebCrypto, not the Android native module. Trust and cloud acknowledgement are deliberately simulated.

What the lab proves

The browser creates an Ed25519 keypair, canonicalizes the unsigned event fields, computes a SHA-256 event ID, and signs the canonical UTF-8 bytes. The receiver independently recomputes the ID and verifies the Ed25519 signature before the demo author policy is consulted.

What it does not prove

The author allowlist is a local switch, not Vanguard’s server-signed campus registry. Relay hops are mutable and unauthenticated. “Simulate cloud ack” only changes this page’s demo state; it does not contact Supabase or mark any real database row confirmed.

Event envelope

The v1 signed envelope has exactly eight fields. The event ID and Ed25519 signature cover the same canonical unsigned representation; neither covers the signature field or ID itself.

{
  version: 1,
  id: "base64url(SHA-256(unsigned))",
  type: "message.created",
  authorPublicKey: "Ed25519 SPKI / base64url",
  createdAtEpochMs: 1700000000000,
  expiresAtEpochMs: null,
  payloadCanonicalJson: "{...}",
  signature: "Ed25519 / base64url"
}

Ingress acceptance order

Incoming bytes are bounded and parsed as a relay frame. The receiver applies its own hop ceiling, checks expiry, verifies the signature and event ID, asks an injected fail-closed author-trust policy, then calls the durable repository. Unknown authors never become trusted by default.

Protocol rules worth remembering

  • Never mutate the author-signed envelope while relaying.
  • Hop count, path, receipts and retry metadata stay outside the signed envelope.
  • A signature proves key control, not a student’s identity or campus membership.
  • Unknown, suspended, revoked, expired or stale registry keys fail closed.
  • Unconfirmed events are not silently deleted to satisfy the storage budget.
  • Cloud confirmation requires an explicit acknowledgement for that event ID.

Build and development

Requirements from the active branch README: Node.js 22.13+, JDK 17 and Android SDK. A physical Android device is required to validate Nearby, permissions, radio state, background execution and Keystore behavior.

npm install
npx expo install --fix
npm run typecheck
npm test
npm run doctor
npx expo prebuild --platform android
npm run android

Native app builds require a development build; npm run ios exists as a package script, but the Vanguard iOS transport is not implemented.
